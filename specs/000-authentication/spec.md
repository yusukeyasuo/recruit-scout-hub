# 機能仕様: 認証機能

**Feature Branch**: `000-authentication`
**作成日**: 2026-02-08
**ステータス**: Draft

## ユーザーシナリオ & テスト（必須）

### ユーザーストーリー1 - ログイン (優先度: P1)

ユーザーとして、メールアドレスとパスワードでログインし、アプリケーションにアクセスしたい。

**この優先度の理由**: 認証機能の最も基本的な機能。これがないとシステムを保護できない。MVP（最小viable product）として最優先。

**独立テスト**: ログインフォームにメールアドレスとパスワードを入力し、ログインボタンをクリックすることで、セッションが作成され、ダッシュボードにリダイレクトされることを確認できる。

**受け入れシナリオ**:

| # | Given（前提条件） | When（操作） | Then（期待結果） |
|---|---|---|---|
| 1 | ユーザーが未ログイン状態 | ログインページにアクセス | ログインフォーム（メール、パスワード入力欄）が表示される |
| 2 | 有効なユーザーアカウントが存在する | 正しいメールとパスワードを入力してログインボタンをクリック | ログインに成功し、ダッシュボードにリダイレクトされる |
| 3 | ログインフォームが表示されている | 間違ったパスワードを入力してログイン | 「メールアドレスまたはパスワードが正しくありません」というエラーメッセージが表示される |
| 4 | ログインフォームが表示されている | 存在しないメールアドレスを入力してログイン | 「メールアドレスまたはパスワードが正しくありません」というエラーメッセージが表示される（セキュリティのため同じメッセージ） |
| 5 | ログインフォームが表示されている | メールまたはパスワードが未入力でログイン | バリデーションエラーが表示される |

---

### ユーザーストーリー2 - ログアウト (優先度: P1)

ユーザーとして、ログアウトして安全にセッションを終了したい。

**この優先度の理由**: セキュリティの基本機能。共有PCなどでログアウトできないと個人情報が漏洩するリスクがある。

**独立テスト**: ログイン状態でログアウトボタンをクリックすることで、セッションが破棄され、ログインページにリダイレクトされることを確認できる。

**受け入れシナリオ**:

| # | Given（前提条件） | When（操作） | Then（期待結果） |
|---|---|---|---|
| 1 | ユーザーがログイン済み | ヘッダーの「ログアウト」ボタンをクリック | セッションが破棄され、ログインページにリダイレクトされる |
| 2 | ログアウト後 | 保護されたページ（例: /job-descriptions）にアクセスしようとする | ログインページにリダイレクトされる |
| 3 | ログアウト後 | ブラウザの戻るボタンを押す | ログインページにリダイレクトされる（キャッシュされたページは表示されない） |

---

### ユーザーストーリー3 - セッション管理 (優先度: P1)

ユーザーとして、一度ログインしたら7日間は再ログイン不要で利用したい。また、7日間経過したら自動的にログアウトされセキュリティを確保したい。

**この優先度の理由**: ユーザビリティとセキュリティのバランス。毎回ログインは不便だが、無期限セッションはセキュリティリスク。

**独立テスト**: ログイン後、7日以内にアクセスすればログイン状態が維持され、7日経過後にアクセスするとログインページにリダイレクトされることを確認できる。

**受け入れシナリオ**:

| # | Given（前提条件） | When（操作） | Then（期待結果） |
|---|---|---|---|
| 1 | ユーザーがログイン済み | ブラウザを閉じて再度開く | セッションが維持され、ログイン状態のまま |
| 2 | ログインから6日経過 | アプリケーションにアクセス | ログイン状態が維持されている |
| 3 | ログインから7日経過 | アプリケーションにアクセス | セッションが期限切れとなり、ログインページにリダイレクトされる |
| 4 | セッション期限切れ | ログインページにリダイレクト後 | 「セッションの有効期限が切れました。再度ログインしてください」というメッセージが表示される |

---

### ユーザーストーリー4 - 保護されたルート (優先度: P1)

システムとして、未認証ユーザーが保護されたページ（JD管理、候補者管理など）にアクセスできないようにしたい。

**この優先度の理由**: 認証機能の最も重要な目的。これがないと認証の意味がない。

**独立テスト**: 未ログイン状態で保護されたページのURLに直接アクセスしようとすると、ログインページにリダイレクトされることを確認できる。

**受け入れシナリオ**:

| # | Given（前提条件） | When（操作） | Then（期待結果） |
|---|---|---|---|
| 1 | ユーザーが未ログイン | 保護されたページ（/job-descriptions）にアクセス | ログインページにリダイレクトされる |
| 2 | ユーザーが未ログイン | 保護されたAPI（/api/job-descriptions）にアクセス | 401 Unauthorizedエラーが返される |
| 3 | ユーザーがログイン済み | 保護されたページ（/job-descriptions）にアクセス | 正常にページが表示される |
| 4 | ログインページから保護されたページにリダイレクトされた | ログインに成功 | 元々アクセスしようとしていたページにリダイレクトされる（リダイレクトURL保持） |

---

### ユーザーストーリー5 - ユーザー招待（新規ユーザー追加） (優先度: P2)

既存ユーザーとして、新しいユーザーをシステムに招待し、アカウントを作成させたい。

**この優先度の理由**: 初期ユーザー作成後、チームメンバーを追加する手段。個人利用からチーム利用への移行に必要。P1ほど緊急ではないが、実用上重要。

**独立テスト**: ログイン済みユーザーが招待フォームでメールアドレスを入力し、招待リンクが生成され、そのリンクから新規ユーザーが登録できることを確認できる。

**受け入れシナリオ**:

| # | Given（前提条件） | When（操作） | Then（期待結果） |
|---|---|---|---|
| 1 | ユーザーがログイン済み | 「ユーザー招待」ページにアクセス | 招待フォーム（メールアドレス入力欄）が表示される |
| 2 | 招待フォームが表示されている | 招待したいメールアドレスを入力して送信 | 招待リンクが生成され、画面に表示される（メール送信なし） |
| 3 | 招待リンクが生成されている | 招待リンクをコピーして相手に共有 | 相手が招待リンクにアクセスできる |
| 4 | 新規ユーザーが招待リンクにアクセス | 名前とパスワードを入力して登録ボタンをクリック | アカウントが作成され、自動的にログインしてダッシュボードにリダイレクトされる |
| 5 | 招待リンクから登録完了 | 次回以降のアクセス | 作成したメールアドレスとパスワードでログインできる |
| 6 | 招待リンクが既に使用済み | 同じ招待リンクに再度アクセス | 「この招待リンクは既に使用されています」というエラーメッセージが表示される |
| 7 | 招待リンクが7日以上経過 | 期限切れの招待リンクにアクセス | 「この招待リンクは有効期限が切れています」というエラーメッセージが表示される |

### エッジケース

- パスワードに特殊文字が含まれる場合、正しくハッシュ化・検証できるか？
- 非常に長いパスワード（例: 100文字以上）を入力した場合、システムがクラッシュしないか？（文字数制限の設定）
- 同時に複数のセッションでログインした場合（複数デバイス）、両方有効か？
- ログイン試行を短時間に大量に行った場合、ブルートフォース攻撃対策はあるか？（レートリミット）
- メールアドレスの大文字・小文字の違い（example@test.comとEXAMPLE@TEST.COM）は同一ユーザーとして扱うか？
- 既に登録済みのメールアドレスで招待リンクを生成しようとした場合、エラーまたは警告を表示するか？
- 招待リンクのトークンが推測されにくい十分なランダム性を持っているか？
- セッションクッキーにHttpOnly、Secure、SameSite属性が設定されているか？（XSS、CSRF対策）

## 要件（必須）

### 機能要件

| ID | 要件 | 優先度 |
|---|---|---|
| FR-001 | システムは、メールアドレスとパスワードでユーザーをログインさせることができなければならない | P1 |
| FR-002 | システムは、パスワードをbcryptでハッシュ化して保存しなければならない | P1 |
| FR-003 | システムは、ログイン失敗時に「メールアドレスまたはパスワードが正しくありません」という汎用エラーメッセージを表示しなければならない（セキュリティ） | P1 |
| FR-004 | システムは、ユーザーがログアウトできなければならない | P1 |
| FR-005 | システムは、セッションをJWTトークンとして管理しなければならない（NextAuth.js） | P1 |
| FR-006 | システムは、セッションの有効期限を7日間に設定しなければならない | P1 |
| FR-007 | システムは、セッション期限切れ時にログインページにリダイレクトしなければならない | P1 |
| FR-008 | システムは、未認証ユーザーが保護されたページにアクセスできないようにしなければならない | P1 |
| FR-009 | システムは、未認証ユーザーが保護されたAPIにアクセスした場合、401 Unauthorizedを返さなければならない | P1 |
| FR-010 | システムは、ログイン後、元々アクセスしようとしていたページにリダイレクトしなければならない | P2 |
| FR-011 | システムは、既存ユーザーが新規ユーザーを招待できなければならない | P2 |
| FR-012 | システムは、招待リンクを生成し、7日間有効にしなければならない | P2 |
| FR-013 | システムは、招待リンクから新規ユーザーがアカウント（名前、パスワード）を作成できなければならない | P2 |
| FR-014 | システムは、招待リンクが一度使用されたら無効化しなければならない | P2 |
| FR-015 | システムは、期限切れまたは無効な招待リンクへのアクセスを拒否しなければならない | P2 |
| FR-016 | システムは、メールアドレスを小文字に正規化して保存しなければならない（大文字・小文字の違いを吸収） | P1 |
| FR-017 | システムは、入力値のバリデーション（メール形式、パスワード最小長）を実施しなければならない | P1 |

### 主要エンティティ

**User（ユーザー）**: アプリケーションのユーザーアカウント

| フィールド名 | 型 | 必須/任意 | 説明 |
|---|---|---|---|
| `id` | UUID | 必須 | 一意識別子（自動生成） |
| `email` | string | 必須 | メールアドレス（ユニーク、小文字正規化） |
| `password` | string | 必須 | パスワードハッシュ（bcrypt） |
| `name` | string | 必須 | ユーザー名 |
| `createdAt` | timestamp | 必須 | 作成日時（自動記録） |
| `updatedAt` | timestamp | 必須 | 最終更新日時（自動記録） |

**Invitation（招待）**: 新規ユーザー招待の管理

| フィールド名 | 型 | 必須/任意 | 説明 |
|---|---|---|---|
| `id` | UUID | 必須 | 一意識別子（自動生成） |
| `email` | string | 必須 | 招待されたメールアドレス |
| `token` | string | 必須 | 招待リンクのトークン（ユニーク、ランダム生成） |
| `invitedById` | UUID | 必須 | 招待したユーザーのID（外部キー → User） |
| `used` | boolean | 必須 | 招待が使用済みかどうか（デフォルト: false） |
| `expiresAt` | timestamp | 必須 | 招待リンクの有効期限（作成日時 + 7日） |
| `createdAt` | timestamp | 必須 | 作成日時（自動記録） |

**リレーション**:
- 1人のUserは複数のInvitationを作成できる（1対多、invitedBy関係）

## 成功基準（必須）

### 測定可能な成果

| ID | 成功基準 | 測定方法 |
|---|---|---|
| SC-001 | ユーザーは、ログインを10秒以内に完了できる | 平均ログイン時間の測定 |
| SC-002 | パスワードハッシュ化は0.5秒以内に完了する | bcryptハッシュ化処理時間の測定 |
| SC-003 | 未認証ユーザーの保護されたページへのアクセスを100%ブロックする | E2Eテスト |
| SC-004 | セッション管理は100%正確に7日間で期限切れになる | 統合テスト |
| SC-005 | ユーザーの90%が、初回利用時にガイドなしでログインできる | ユーザビリティテスト |
| SC-006 | 招待リンクの生成から新規ユーザー登録まで3分以内に完了できる | 平均所要時間の測定 |
| SC-007 | システムは、SQLインジェクション攻撃を100%防御する | セキュリティテスト（Prisma ORM使用） |
